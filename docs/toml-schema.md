# TOML Схема

## Блок `[main]`
`name` определяет имя раскладки.
`short_name` используется как короткий идентификатор.

### `caps_is_shift`

Default: true. Определяет поведение раскладки при включённом <kbd>CapsLock</kbd>:
- `true` — стандартное поведение. Символы, определённые в слоях `caps` и `caps_shift` напрямую связаны с `base_shift` и `base` слоями соответственно. `ISO_Next_Group` не включается в раскладку, группа только одна.
- `false` — альтернативное поведение. Символы, определённые в слоях `caps` и `caps_shift` самостоятельны и не связаны с `base_shift` и `base`. `ISO_Next_Group` переключает внутренние группы (non-caps / caps).

> [!NOTE]
> `@Trans` в `caps` и `caps_shift` слоях резолвится в `base` и `base_shift`.

## Блок `[msklc]`
Нужен для корректной генерации раскладок для Windows.
В нём указываются поля, которые будут отображаться в системных
настройках, в инсталляторе/деинсталляторе, а также в system-tray.

## Блок `[macos]`

Весь блок опционален, все поля — тоже (дефолты ниже).
Метаданные macOS-бандла; маппинг на файлы — в `docs/10-macos-keylayout.md`:

```toml
[macos]
bundle_id = "com.clayde.layout"          # CFBundleIdentifier
bundle_name = "My Layout"                # CFBundleName (дефолт =[main].name)
bundle_version = "1.0"                   # CFBundleVersion (semver)
keyboard_name = "MyKB"                   # имя .keylayout, <keyboard name>, KLInfo_<name> (дефолт =буквы short_name)
capslock_language_switch_capable = false # TICapsLockLanguageSwitchCapable
icon_is_template = false                 # TISIconIsTemplate (иконки .icns пока нет)
input_source_id = "com.clayde.layout.mykb" # TISInputSourceID (дефолт =${bundle_id}.${keyboard_name.toLowerCase()})
intended_language = "en"                 # TISIntendedLanguage (две латинские буквы)
build_version = "1.0"                    # BuildVersion (semver)
project_name = "My Layout"               # ProjectName (дефолт =[main].name)
source_version = "1.0"                   # SourceVersion (semver)
icon_path = "psi.icns"                   # путь к .icns относительно каталога схемы → Resources/<keyboard_name>.icns
```

## Блок `[ligatures]`

В этом блоке можно определить **лигатуры** — когда при нажатии одной клавиши
вводится сразу несколько символов (от 2 до 4). Это удобно для ввода каких-нибудь
сочетаний вроде `=>`, `->`, ` - ` и т.д.

> [!IMPORTANT]
> Лигатуры **не поддерживаются** в Linux и будут заменены на пустую клавишу!

> [!WARNING]
> Для Windows, лигатуры в слоях `caps` и `caps_shift` не поддерживаются системой.

**Определение**:
```toml
[ligatures]
FatArr = "=>"
ThinArr = "->"
```

**Использование**:
```
@FatArr @ThinArr
```

## Сетка клавиш

Сетка клавиш стандартной 104-105-клавишной клавиатуры вписана в 5×10:

```
1     2     3     4     5     6     7     8     9     0
Q     W     E     R     T     Y     U     I     O     P
A     S     D     F     G     H     J     K     L     ;
Z     X     C     V     B     N     M     ,     .     /
Space ~     -     =     [     ]     \     '     ISO_\ Num_.
```

Это покрывает все символьные клавиши, которые можно переопределить
в системах Windows, Linux и macOS. F-* и Control-клавиши не обрабатываются.

> [!NOTE]
> Зачем переопределять пробел? Он же и в Африке пробел...
>
> На пробел в некоторых случаях можно назначить символ **неразрывного пробела**.
> Он выглядит как обычный пробел, однако «склеивает» между собой слова.
> Полезно его ставить, если вы не любите висячие предлоги, союзы и т.д.
>
> Символ неразрывного пробела определён как `@Nbsp`.

> [!NOTE]
> Чтобы обозначить клавишу как пустую, используйте `@None`.
>
> Также, на слоях `caps` и `caps_shift` доступен `@Trans`.
> Он позволяет игнорировать Caps-состояние и наследует
> символы из `base` и `base_shift` соответственно.
> Слои `caps`/`caps_shift` обязательны: системный CapsLock затрагивает
> только буквы, поэтому цифры/пунктуация в `SGCap`-зоне (ряды 2–4)
> размечаются `@Trans` (в KLC — `Cap 0` без расширения)

> [!NOTE]
> В сетку клавиш можно вписывать любые ASCII и Unicode символы.
> Однако, поддерживаются только коды с максимальным диапазоном в 0xFFFF.
> Для эмодзи и других символов вне этого диапазона используйте лигатуры.

## Слои

Системные раскладки поддерживают следующие слои:

| Слой        | Описание                                                  |
| ----------- | --------------------------------------------------------- |
| base        | Базовый слой, в котором по-умолчанию находится клавиатура |
| base_shift  | Слой, который актвивруется зажатием только клавиши Shift  |
| altgr       | Слой, который активируется зажатием только клавиши AltGr  |
| altgr_shift | Слой, который активируется зажатием AltGr + Shift         |
| caps        | Слой включается при однократном нажатии CapsLock          |
| caps_shift  | Слой включается при нахождении в CapsLock-слое + Shift    |

> [!NOTE]
> Также, в системных раскладках есть слой, который активируется при зажатии Ctrl/Cmd,
> однако, для совместимости с программами очень **не рекомендуется** его изменять.
>
> Поэтому, в данной утилите ctrl и ctrl_shift слои намеренно **не поддерживаются**.

> [!NOTE]
> В стандартных системных раскладках CapsLock затрагивает только буквенные клавиши:
> для букв `caps` совпадает с `base_shift`, а `caps_shift` — с `base`,
> для остальных символов (цифры, пунктуация) используется `@Trans`
> (наследование из `base`/`base_shift`, в KLC — `Cap 0` без расширения).
>
> С помощью задания `caps` и `caps_shift` слоёв можно реализовать виртуальное
> переключение раскладки, например между EN и RU символами (см. пример Universal-Layout)
