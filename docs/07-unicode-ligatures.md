# Символы, Unicode-коды и лигатуры

## 1. Зачем нужен отдельный артефакт

`.klc` хранит не символы, а hex-коды (`002d`, `00ab`, `2014`) плюс английские
имена в комментариях (`HYPHEN-MINUS`, `LEFT-POINTING DOUBLE ANGLE...`).
TOML хранит символы (`-`, `«`, `—`). Между ними нужен мост:

- прямое отображение `символ -> строчный 4-hex код` для колонок `LAYOUT`
  и `LIGATURE`;
- обратное справочное `код -> UPPER_ENGLISH_NAME` для комментариев;
- раскрытие лигатур `имя -> [коды]` для секции `LIGATURE`.

Без этого моста генератор не сможет ни закодировать `₽` как `20bd`,
ни подписать его в комментарии, ни разложить `=>` в `003d 003e`.

## 2. Формат таблицы соответствия

Предложение: статический файл данных в репозитории, например
`data/unicode.json` вида:

```json
{ "002d": "HYPHEN-MINUS", "00ab": "LEFT-POINTING DOUBLE ANGLE QUOTATION MARK", "...": "..." }
```

Ключ — строчный hex без префикса, значение — имя в верхнем регистре как
в эталонах. Прямое кодирование символа в hex таблице не требует:
`hex = codePoint.toString(16).padStart(4, "0")` вычисляется в рантайме.
Таблица нужна только для имён в комментариях.

Источник имён: `UnicodeData.txt` (публичный файл Консорциума Unicode,
поле 1 — имя). На этапе реализации скриптом извлекаются имена всех символов,
встречающихся в `layouts/` плюс разумный запас (латиница, кириллица, греческий,
типографика, стрелки, дроби, надстрочные). Полную базу Unicode тащить
в репозиторий не нужно: неизвестное имя — не ошибка, а комментарий `<null>`
(так в эталоне подписан `₽`: код `20bd`, комментарий `<null>`; и `%%`-ячейки
`K` в `altgr` тоже имеют `<null>` в основной строке, так как символа там нет).

Правила:

1. Поиск имени — по коду, без учёта регистра; отсутствие — `<null>`
   и предупреждение `W_UNICODE_NONAME` на стадии валидации (не блокирует).
2. Имена с `*` в эталоне (`...QUOTATION MARK *`) — особенность MSKLC для
   «печатаемых» кавычек; воспроизводить звёздочку только если она есть
   в эталоне для конкретного символа? Нет: звёздочка в эталоне стоит у
   `00ab`/`00bb` (`«`, `»`). Правило: таблица хранит имена без звёздочки,
   генератор добавляет ` *` для кодов `00ab` и `00bb` (единственные случаи
   в эталонах). Зафиксировать golden-тестом.
3. Символы вне BMP (`codePoint > 0xFFFF`): hex longer than 4, в KLC
   непредставим как одна колонка. Решение первой версии: генератор
   отвергает их `G_UNICODE_ASTRAL` (см. `docs/06-generation-windows.md`).
   Если позже выяснится, что MSKLC принимает суррогатные пары в `LIGATURE`,
   ограничение ослабляется точечно для лигатур.

## 3. Встроенные токены

Не требуют таблицы, обрабатываются раньше неё:

- `@None` → колонка `-1`, в комментарии `<none>`;
- `@Space` → `0020`, имя `SPACE`;
- `@Nbsp` → `00a0`, имя `NO-BREAK SPACE`.

## 4. Лигатуры: от `@Имя` до секции `LIGATURE`

Жизненный цикл одной лигатуры на примере `@FatArr` (`FatArr = "=>"`):

1. Автор пишет в `[ligatures]` значение `"=>"` (2 символа).
2. Валидатор (V4) разбирает его в кодпоинты `[U+003D, U+003E]`, проверяет
   длину 1–4 и отсутствие управляющих символов.
3. Автор ставит `@FatArr` в ячейку сетки, например `altgr` `r3c8`.
4. Валидатор (V6) проверяет, что имя определено, и резолвит ячейку
   в `LigatureRef(FatArr)`.
5. Генератор при обходе клавиши `r3c8` (`SC 25`, `VK K`) видит, что состояние
   `s6` — лигатура: в `LAYOUT` пишет `%%` в колонку `6`, а в список лигатур
   добавляет запись `(VK=K, Mod#=3, codes=[003d, 003e])`.
6. Та же клавиша в `altgr_shift` содержит `@ThinArr` (`->` → `002d 003e`):
   в `LAYOUT` вторая `%%` (колонка `7`), в списке — `(VK=K, Mod#=4, ...)`.
7. Секция `LIGATURE` пишется из списка (сортировка: scancode, `Mod#`),
   комментарий — из имён кодов: `EQUALS SIGN + GREATER-THAN SIGN`.

Важные детали:

- Одна лигатура, использованная в N местах, даёт N строк `LIGATURE`
  (по одной на каждое место+состояние), а не одну. Ключ строки —
  `(VK, Mod#)`, не имя лигатуры. Имя из TOML в `.klc` не попадает вообще.
- Лигатура в `base`/`base_shift` обрабатывается тем же кодом (`Mod# 0/1`);
  в примерах такого нет, но алгоритм это поддерживает. MSKLC 1.4 фиксил
  именно AltGr-лигатуры, базовые работали всегда.
- Лигатура в `caps`/`caps_shift` запрещена генератором (`G_CAPS_LIGATURE`):
  для caps-расширений MSKLC не предоставляет `Mod#`, и молчаливая запись
  неверных данных хуже честной ошибки.
- Неиспользованная лигатура из `[ligatures]` в `.klc` не попадает
  (предупреждение `W_LIG_UNUSED`).
