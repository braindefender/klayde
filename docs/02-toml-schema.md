# Схема TOML-файла раскладки

## 1. Общий вид

Файл состоит ровно из четырёх секций верхнего уровня. Порядок секций
рекомендуемый, но не обязательный (кроме того, что `[layout]` идёт последней
ради читаемости). Неизвестные секции и неизвестные ключи внутри известных
секций запрещены — это ошибка `E_SCHEMA_UNKNOWN_KEY`, чтобы опечатки
(`base_shfit`) не превращались в молчаливую потерю слоя.

```toml
[main]
name = "Universal Layout Ortho Merged"
short_name = "ULOM"
caps_is_shift = false

[msklc]
name = "ULOM"
company = "braindefender"
copyright = "©2026 braindefender"
description = "Universal Layout Ortho Merged"

[ligatures]
FatArr = "=>"
ThinArr = "->"

[layout]
base = '''
...
'''
base_shift = '''
...
'''
altgr = '''
...
'''
altgr_shift = '''
...
'''
caps = '''
...
'''
caps_shift = '''
...
'''
```

Примеры в `layouts/`: все схемы содержат 6 слоёв
(включая `caps`/`caps_shift` с `@Trans` для не-букв).

## 2. Правило кавычек `'''` (критично)

Все строковые поля внутри `[layout]` и значения в `[ligatures]` обязаны быть
оформлены тройными **одинарными** кавычками `'''` (literal strings по TOML),
а не тройными двойными `"""` (basic strings).

Причина: в basic strings обратный слэш `\` — escape-символ, и значение
`"\"` превратится не в один символ слэша, а в ошибку парсинга или в другой
символ. Раскладки содержат `\` как обычный символ (слой `altgr`, нижний ряд),
поэтому единственный безопасный вариант — literal strings, где `\` это
просто `\`.

Контроль выполняется **до** TOML-парсинга, по сырому тексту файла
(см. `docs/03-validation.md`, валидатор `V0_RawQuotes`): наличие подстроки
`"""` в любом месте файла — ошибка `E_QUOTES_TRIPLE_DOUBLE` с номером строки.
Дополнительно после парсинга проверяется, что каждое поле слоя — строка
(тип уже гарантирует literal/basic, но сырая проверка надёжнее, так как
TOML-парсер к этому моменту уже мог исказить слэши).

## 3. Секция `[main]`

| Ключ           | Тип     | Обязат. | Правила                                                                                           |
| -------------- | ------- | ------- | ------------------------------------------------------------------------------------------------- |
| `name`         | string  | да      | 1–64 символа, не пустой после trim. Используется для имени `.klc`-файла и `DESCRIPTIONS`.         |
| `short_name`   | string  | да      | 1–8 символов, латиница/цифры/дефис, без пробелов (дефис только внутри: `EN-US` — да, `-EN` — нет). Используется в логах и как кандидат для будущих имён. |
| `caps_is_shift`| boolean | нет     | Режим CapsLock (см. `docs/toml-schema.md`): `true` — стандарт (caps связаны с base), `false` — независимые caps. По умолчанию `true`; не-boolean — `E_SCHEMA_TYPE`. |

Ограничение `short_name` выведено из практики MSKLC (короткие идентификаторы
типа `ULOM`, `ULOEN`); точную верхнюю границу MSKLC не документирует явно,
поэтому 8 — консервативный выбор, зафиксированный как валидатор
`E_MAIN_SHORT_NAME`. Дефис внутри идентификатора MSKLC принимает
(например `EN-US`), поэтому он разрешён, но только не с краю.

## 4. Секция `[msklc]`

Метаданные для шапки `.klc`. Все поля обязательные, все — непустые строки после trim.

| Ключ          | Назначение в `.klc`                                                              |
| ------------- | -------------------------------------------------------------------------------- |
| `name`        | Поле `KBD <name>` (например `ULOM`). Латиница/цифры/дефис, без пробелов, 1–8 символов (дефис только внутри). |
| `company`     | Поле `COMPANY`.                                                                  |
| `copyright`   | Поле `COPYRIGHT`.                                                                |
| `description` | Поле `KBD ... "<description>"`.                                                  |

Открытые вопросы, зафиксированные как решения на этапе реализации
(см. `docs/04-klc-format.md`):
`LOCALEID`/`LOCALENAME` (`00000409`/`en-US` в эталонах) и `LANGUAGENAMES`
(`Universal Layout Ortho` в эталоне против `Universal Layout Ortho Merged`
в `DESCRIPTIONS`) в текущих TOML отсутствуют. Предложение: добавить
опциональные ключи `localeid`, `localename`, `language_name` в `[msklc]`
с дефолтами `00000409`, `en-US`.
До решения генератор использует дефолты `00000409`/`en-US`, а `LANGUAGENAMES`
пишет равным `DESCRIPTIONS` и фиксирует расхождение с эталоном как известное
отличие.

## 5. Секция `[ligatures]`

Словарь `Имя -> последовательность символов`. Пример: `FatArr = "=>"`.

Правила:

1. Имя: `[A-Za-z][A-Za-z0-9_]*`, 1–32 символа. Регистр важен
   (`@FatArr` и `@fatarr` — разные имена).
2. Зарезервированные имена запрещены: `None`, `Space`, `Nbsp`
   (любой регистр) — они встроены (см. раздел 7). Ошибка `E_LIG_RESERVED`.
3. Значение: 1–4 символа Unicode scalar values. На практике используются
   2 (`=>`, `->`). Значение из 1 символа бессмысленно (это не лигатура) —
   ошибка `E_LIG_LENGTH`. Больше 4 — ошибка `E_LIG_LENGTH`, так как секция
   `LIGATURE` в KLC имеет ровно колонки `Char0..Char3`.
4. Значение не может содержать `@` в начале (чтобы не путать со ссылкой) —
   фактически любое содержимое разрешено, кроме переводов строки и таба;
   перевод строки внутри значения — ошибка `E_LIG_CONTROL`.
5. Дубликаты имён в TOML невозможны технически (парсер отклонит), дубликат
   со встроенными — см. правило 2.
6. Неиспользуемая лигатура (определена, но нигде не referenced) — не ошибка,
   а предупреждение `W_LIG_UNUSED`. Удалять её из KLC-вывода: в `LIGATURE`
   попадают только реально использованные лигатуры.

## 6. Секция `[layout]`

### 6.1. Состав слоёв

Обязательные слои: `base`, `base_shift`, `altgr`, `altgr_shift`,
`caps`, `caps_shift` — все 6 всегда присутствуют. Отсутствие любого —
ошибка `E_SCHEMA_UNKNOWN_KEY` (V2).

Причина обязательности `caps`/`caps_shift`: системный CapsLock
затрагивает **только буквенные** клавиши. Старый режим «без caps —
SGCap для всех 30 клавиш рядов 2–4» неверен для пунктуации/цифр
в этих рядах (например `~`, `&`, `[`, `]` получали шифтованные
caps-расширения). Поэтому автор схемы явно указывает для каждой
позиции: буква — значение caps, не-буква — `@Trans` (без эффекта
CapsLock, в KLC `Cap 0` без расширения).

Семантика слоёв:

- `base` — нажатие без модификаторов (колонка 0 в KLC).
- `base_shift` — Shift (колонка 1).
- `altgr` — Ctrl+Alt / правый Alt (колонка 6, `Mod# 3` для лигатур).
- `altgr_shift` — Shift+Ctrl+Alt (колонка 7, `Mod# 4` для лигатур).
- `caps` — CapsLock (расширение `SGCap`, либо `Cap 0`/`Cap 1` без
  расширения при прозрачности/swap — см. ниже и `@Trans`).
- `caps_shift` — CapsLock+Shift (аналогично).

Чтобы не дублировать символы, которые не должны капитализироваться
при CapsLock (цифры, пунктуация, служебные), в `caps`/`caps_shift`
доступен спец. код `@Trans`: `caps=@Trans` наследует значение из `base`,
`caps_shift=@Trans` — из `base_shift` (включая `@None`/`@Space`/`@Nbsp`,
одиночные символы и `@Лигатуры`). В KLC такая клавиша пишется как
`Cap 0` без расширения (CapsLock без эффекта, нативно для MSKLC).
Явная пара caps, совпавшая со swap (`caps==shift`), пишется как `Cap 1`
без расширения (нативный caps=shift MSKLC).

### 6.2. Формат слоя

Каждый слой — одна literal-строка `'''...'''`, содержащая ровно 5 строк
(разделитель — `\n`; допускаются `\r\n`, нормализуются). Каждая строка —
ровно 10 ячеек. Ячейки разделены **одним или более пробелами** (в примерах —
выравнивание колонок восемью пробелами).

Табуляция как разделитель запрещена (`E_GRID_TAB`): она визуально неотличима и ломает выравнивание.

Пустые строки в начале/конце значения (сразу после `'''` и перед закрывающим
`'''`) игнорируются: в примерах значение начинается с `\n` и заканчивается
`\n`. Значимые пустые строки внутри (пропущенная строка) запрещены.

### 6.3. Формат ячейки

После trim ячейка — ровно одно из:

- `@None` — пустая клавиша (в KLC `-1`). Только это написание; `@none`,
  `@NONE` запрещены (строгая чувствительность к регистру, иначе опечатки).
- `@Space` — `U+0020`.
- `@Nbsp` — `U+00A0` (no-break space).
- `@Trans` — наследование из базового слоя, только в `caps`/`caps_shift`
  (`caps←base`, `caps_shift←base_shift`); в остальных слоях — ошибка
  `E_CELL_AT`. Только это написание; `@trans` запрещён.
- `@Имя` — ссылка на лигатуру из `[ligatures]` (`@` + имя по правилу 5.1).
  Неопределённое имя — ошибка `E_CELL_UNKNOWN_REF`.
- один символ — любой Unicode scalar value, кроме управляющих
  (`Cc`, `Cf` без явного разрешения), кроме пробела (только через `@Space`),
  кроме `@` в начале (резерв ссылок, самостоятельный символ `@` разрешить - это at-sign).
  Таб и перевод строки невозможны конструктивно.

Строгость к регистру `@`-токенов намеренная: `@space` — ошибка
`E_CELL_UNKNOWN_REF` с подсказкой «возможно, имелось в виду `@Space`»
(расстояние Левенштейна ≤ 2 — подсказка, иначе без неё).

Многосимвольная ячейка без `@` (например `=>` напрямую) запрещена:
ошибка `E_CELL_LENGTH` с подсказкой вынести в `[ligatures]`.
Это гарантирует, что каждая не-лигатурная ячейка KLC — ровно один код.

## 7. Встроенные токены

| Токен    | Unicode | KLC-представление | Комментарий                                           |
| -------- | ------- | ----------------- | ----------------------------------------------------- |
| `@None`  | —       | `-1`              | Пусто.                                                |
| `@Space` | U+0020  | `0020`            | Обычный пробел.                                       |
| `@Nbsp`  | U+00A0  | `00a0`            | Неразрывный пробел.                                   |
| `@Trans` | —       | копия base-слоя   | Только caps/caps_shift; в KLC `Cap 0` без расширения. |

Доступны без объявления в `[ligatures]`. Переопределение запрещено
(имена `None`, `Space`, `Nbsp`, `Trans` зарезервированы в любом регистре).
