# Валидация схем

Принцип: валидация — отдельная фаза до генерации. Любая ошибка валидации
блокирует генерацию для **всех** файлов (fail-closed), чтобы не выпускать
частично корректный набор раскладок. Предупреждения (`W_...`) не блокируют.

## 1. Порядок стадий

Стадии идут в фиксированном порядке от дешёвых к дорогим. Каждая стадия
работает только если предыдущие для этого файла прошли. Ошибки собираются
по всем файлам.

**V0. Сырая проверка кавычек (до парсинга).**
Сканировать сырой текст файла построчно. Если найдена подстрока `"""` —
ошибка `E_QUOTES_TRIPLE_DOUBLE` с номером строки и позицией. Продолжать
парсинг бессмысленно? Нет: парсинг всё равно пробуем, чтобы собрать и
синтаксические ошибки, но помечаем файл как заведомо содержащий нарушение
правила `'''`. Причина отдельной стадии: TOML-парсер уже исказит `\`
в basic strings, и постфактум причину не восстановить.

**V1. Парсинг TOML.**
Парсить строгим парсером. Ошибка синтаксиса — `E_TOML_SYNTAX` с сообщением
парсера (строка/колонка), дальше файл не обрабатывается. Пустой файл —
`E_TOML_EMPTY`.

**V2. Структура секций и ключей.**
Проверить наличие обязательных `[main]`, `[msklc]`, `[layout]`
(`[ligatures]` и `[macos]` опциональны; весь блок `[macos]` может
отсутствовать — все его поля тоже опциональны). В `[layout]` обязательны все 6
слоёв (`base`, `base_shift`, `altgr`, `altgr_shift`, `caps`,
`caps_shift`); отсутствие любого — `E_SCHEMA_UNKNOWN_KEY`.
Неизвестные секции/ключи — `E_SCHEMA_UNKNOWN_KEY`
с указанием пути (`[layout].base_shfit`). Типы значений: всё, что должно
быть строкой, но пришло числом/массивом — `E_SCHEMA_TYPE`.
`[main].caps_is_shift` — необязательный boolean, по умолчанию `true`:
не-boolean значение — `E_SCHEMA_TYPE`. `[macos]`:
9 строковых полей — строки, 2 boolean-поля
(`capslock_language_switch_capable`, `icon_is_template`) — boolean;
нарушение типа — `E_SCHEMA_TYPE`, битое значение отбрасывается и дальше
действует дефолт.

**V3. Скалярные поля `[main]`/`[msklc]`/`[macos]`.**
Проверки из `docs/02-toml-schema.md`: непустота, длины, шаблоны
(`short_name`, `msklc.name`). Каждое нарушение — свой код
(`E_MAIN_NAME`, `E_MAIN_SHORT_NAME`, `E_MSKLC_NAME`, ...), сообщение содержит
фактическое значение. Поля `[macos]` — свои коды `E_MACOS_*`
(версии — числа через точки, `intended_language` — две латинские буквы,
`keyboard_name` — только буквы, `icon_path` — непустой путь к `.icns`);
производные дефолты от битого `[main]`
не проверяются повторно (каскада ошибок нет).
Существование файла `icon_path` (относительно каталога схемы) проверяет
`validateFile` (код тот же, `E_MACOS_ICON_PATH`): чистая `validateText`
без доступа к fs его не видит.

**V4. Словарь `[ligatures]`.**
Для каждой записи: имя по шаблону (`E_LIG_NAME`), не зарезервировано
(`E_LIG_RESERVED`), значение 1–4 scalar values без переводов строки
(`E_LIG_LENGTH`, `E_LIG_CONTROL`). Значение из одного символа —
`E_LIG_LENGTH` (подсказка: одиночный символ пишется прямо в сетку, а не
в лигатуры). Значение разбирается в массив кодпоинтов сразу, чтобы последующие
стадии пользовались уже готовым.

**V5. Геометрия сеток.**
Для каждого из 6 слоёв: нормализовать `\r\n`, отбросить ведущую/конечную
пустую строку, разбить на строки, каждую строку разбить по пробелам на ячейки.
Ожидается 5 строк по 10 ячеек. Нарушение — `E_GRID_GEOMETRY` с деталями
(сколько строк/ячеек фактически, номер проблемной строки). Таб в строке —
`E_GRID_TAB`. Пустая ячейка после сплита — `E_GRID_EMPTY_CELL` с координатами.

**V6. Содержимое ячеек.**
Для каждой ячейки `(слой, строка 1–5, колонка 1–10)` после trim применить
правила раздела 6.3 схемы. Ошибки:
`E_CELL_UNKNOWN_REF` (неизвестная `@`-ссылка; приложить список ближайших
имён), `E_CELL_LENGTH` (многосимвольная ячейка без `@`), `E_CELL_CONTROL`
(управляющий символ), `E_CELL_AT` (ячейка начинается с `@`, но не
соответствует шаблону ссылки). Сообщение всегда содержит сырое содержимое
ячейки в кавычках и координаты.

**V7. Когерентность `caps` (упразднена).**
Слои `caps`/`caps_shift` обязательны через V2; отдельной проверки пары
нет. Исторический код `E_CAPS_HALF` («задан только один из caps») удалён:
половинчатый набор теперь невозможен без ошибки V2
(`E_SCHEMA_UNKNOWN_KEY` за отсутствующий слой). Причина обязательности:
системный CapsLock затрагивает только буквы, поэтому неявный
`caps=shift` для всех 30 клавиш рядов 2–4 неверен для пунктуации/цифр —
автор обязан явно разметить `@Trans` для не-букв.

**V8. Маппируемость в Unicode.**
Каждый одиночный символ слоя и каждый символ каждого значения лигатуры
должен иметь код (всегда true для Unicode) и английское имя для KLC-комментария
(таблица имён может не знать редкий символ — тогда предупреждение
`W_UNICODE_NONAME` и заглушка `<null>` в комментарии, как в эталоне для `₽`:
там комментарий `<null>` при коде `20bd`). Суррогатные половины и не-scalar
значения невозможны после TOML-парсинга, но проверяются явно (`E_UNICODE`).

**V9. Кросс-файловые проверки.**
После обработки всех файлов: дубликаты `msklc.name` (`E_MSKLC_DUP_NAME`),
дубликаты `main.short_name` (предупреждение `W_DUP_SHORT`, не ошибка —
на генерацию не влияет, но сбивает с толку), дубликаты `main.name`
(предупреждение). Проверка, что выходной `.klc`-файл не перезаписывается
двумя входами (следствие дубля `main.name`).
Коллизия выходного macOS-каталога — ошибка `E_MACOS_DUP_BUNDLE`:
ключ — полный путь `<out>/<rel>/macos/<bundle_name>.bundle`, поэтому
одинаковый `bundle_name` в разных подкаталогах `layouts/` — не коллизия,
а в одном каталоге — тихая перезапись, запрещена (fail-closed:
генерация не запускается ни для одного файла).

## 2. Формат сообщений

Каждая ошибка: код, файл, координаты, человеческое описание, фактическое
значение, ожидание. Примеры:

```text
error[E_QUOTES_TRIPLE_DOUBLE] layouts/a.toml:12: найдены тройные двойные кавычки ("""); все сетки и лигатуры со слэшем должны использовать '''...'''
error[E_TOML_SYNTAX] layouts/a.toml:7: TOML-парсинг: expected newline but got ...
error[E_GRID_GEOMETRY] layouts/a.toml :: [layout].base: ожидалось 5 строк по 10 ячеек; строка 2 содержит 9 ячеек
error[E_CELL_UNKNOWN_REF] layouts/a.toml :: [layout].altgr строка 3, колонка 8: "@FatArrr" не определено в [ligatures]; возможно, имелось в виду "@FatArr"
error[E_SCHEMA_UNKNOWN_KEY] layouts/a.toml :: [layout].caps_shift: отсутствует обязательный слой
error[E_MSKLC_DUP_NAME] layouts/b.toml :: [msklc].name "ULOM" уже использован в layouts/a.toml
```

Предупреждения начинаются с `warn[W_...]` и не влияют на код выхода.

## 3. Инварианты, которые валидация гарантирует генератору

После успешной валидации генератор вправе полагаться на то, что:

1. В файле нет `"""`, все слэши — буквальные.
2. Все 6 слоёв — массивы 5×10 нормализованных токенов.
3. Каждый токен — один из: `None | Space | Nbsp | LigatureRef(имя) | Char(c)`,
   где `Char` — ровно один scalar value, `LigatureRef` — резолвится.
4. Все значения лигатур — массивы из 2–4 кодпоинтов.
5. `msklc.name` уникален среди входов.
6. Выходные macOS-каталоги (`<bundle_name>.bundle`) не пересекаются.
6. `main.capsIsShift` известен (boolean): генераторы ветвятся по нему
   без дополнительных проверок (Windows: SGCap при `true` — `G_CAPS_MODE`;
   Linux: одна/две группы).

Благодаря этому генератор не содержит проверок «на всякий случай» —
вся диагностика сосредоточена в валидаторе, а генератор занимается только
раскладкой байтов.

## 4. Алгоритм валидации одного файла (псевдокод словами)

1. Прочитать файл как UTF-8 текст. Ошибка чтения — `E_IO`.
2. Построчно найти `"""` — при нахождении добавить `E_QUOTES_TRIPLE_DOUBLE`
   (по одной на строку, с колонкой первого вхождения).
3. Распарсить TOML. При исключении — `E_TOML_SYNTAX`, завершить файл.
4. Проверить множество секций/ключей (V2). При критических absence —
   пропустить зависимые стадии для отсутствующего.
5. Проверить скаляры `main`/`msklc` (V3).
6. Проверить и нормализовать `[ligatures]` (V4) в карту `имя -> кодпоинты`.
7. Для каждого слоя из присутствующих: нормализовать в матрицу 5×10 (V5),
   затем проверить каждую ячейку (V6) с резолвом ссылок по карте из шага 6.
   Ненормализованные слои дальше не участвуют.
8. V7 зарезервирована (caps обязательны через V2, отдельной проверки нет).
9. Проверить имена Unicode для всех символов (V8) — только предупреждения.
10. Вернуть структуру `ValidatedSpec` или список ошибок.

Кросс-файловая стадия V9 выполняется один раз после цикла по файлам.
